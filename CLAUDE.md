# who-pressed-the-fucking-glyph — рабочий контекст

> Флагманский проект медиа-ниши Эрмека «AI/тулзы для доты». Одновременно: контент (build-in-public, клипаем процесс), продукт, и практика цикла (Fable оркеструет, Codex кодит, Эрмек тестит на живой игре).

## Цель
Реалтайм-оверлей для Dota 2, который показывает то, что игра прячет. Стартовая фича — вечный вопрос **«кто слил глиф?»** (и скан). Мем-бренд = ярость в тимспике, любой дотер понимает мгновенно.

## Где мы сейчас (day 2)
Это **проба GSI**, не сам тул. `server.js` — чистый Node-листенер (без зависимостей) на :3000, ловит POST от доты и:
- перезаписывает полный стейт в `last-state.json` на КАЖДЫЙ фрейм (до троттлов);
- фреймы с непустым `events` → append в `events.jsonl` немедленно (⚡);
- любое изменение ключей с `glyph`/`scan` в пейлоаде → append в `glyph-scan.jsonl` {ts, path, old, new} (🔔);
- консольный обзор (верхние ключи, термины glyph/scan/building/tower/rax/cooldown) — с троттлом 1с.

**Сетап: дота на ДРУГОМ ПК, листенер на этом маке.** Конфиг уже указывает на `http://10.0.0.197:3000/` (LAN IP мака, DHCP — если IP сменится, поправить cfg). Файрвол мака выключен, смоук-тест по LAN прошёл. `gamestate_integration_insomnia.cfg` кладётся на игровом ПК в
`...\Steam\steamapps\common\dota 2 beta\game\dota\cfg\gamestate_integration\` (папку создать, если нет) → перезапустить доту.

## Следующее действие
Эрмек играет бот-матч — за один матч снимаем ДВА зонда:
1. **GSI**: конфиг положен на игровой ПК, `node server.js` на маке, оба в одной сети. В матче нажать глиф и скан по несколько раз, зафиксировать примерное игровое время нажатий.
2. **console.log**: на игровом ПК в Steam → Dota 2 → Свойства → Параметры запуска добавить `-condebug`. После матча забрать файл `...\dota 2 beta\game\dota\console.log` и скинуть на мак — ищем, попадает ли глиф/скан в консольный вывод с ником (лайв-атрибуция без риска).

После — агент разбирает `glyph-scan.jsonl`, `events.jsonl`, `last-state.json` и `console.log`, отвечает на ключевой вопрос: есть ли лайв глиф/скан и атрибуция «кто нажал» (в GSI и/или консоли) → выбор ветки развития.

## Не-варианты (проверено, закрыто)
Читы/ESP с гитхаба «без вмешательства в сервер» — это чтение памяти процесса external-ридером. VAC детектит клиентскую сторону, баны волнами. Противоречит требованию ban-safe → не рассматриваем вообще. Легальные лайв-каналы: GSI, `-condebug` console.log, Overwolf.

## 🔑 Ключевой открытый вопрос (проверить эмпирически)
**Отдаёт ли GSI глиф/скан живьём — и КТО его нажал?**
Гипотеза Fable: «КТО нажал» живьём Valve, скорее всего, НЕ отдаёт (per-player действия в реалтайме прячутся by design, анти-чит логика). Но точно узнаётся только запуском.
→ Как проверить: `node server.js` + положить конфиг + сыграть бот-матч → изучить `last-state.json` (нажать глиф в игре, посмотреть, меняется ли что-то и есть ли атрибуция игрока).

## Продуктовые ограничения (решение Эрмека, 2026-07-29)
1. **Лайв — обязателен.** Пост-гейм разбор реплея — только фолбэк/дополнение, ядро продукта работает во время матча.
2. **Ban-safe — жёсткое требование.** Только официальные механизмы (GSI, Overwolf). Никаких компромиссов ради фич.
3. **Публичный репозиторий — планируется.** Перед публикацией пройти чеклист:

## Легальный ландшафт (важно — не словить бан)
- ✅ **GSI** — официальный API Valve, ban-safe. Только его и используем для лайва.
- ✅ **Overwolf** — легальная платформа оверлеев, если нужен UI поверх игры.
- ❌ Чтение памяти игры / инжект / сторонние ридеры = **VAC-бан**. НЕ делаем никогда.
- 🔁 Фолбэк, если глиф недоступен лайв: **пост-гейм разбор реплея** (OpenDota API / clarity-парсер) — там видно все события, включая кто и когда жал глиф/скан. Пост-гейм существует у конкурентов, поэтому ценность именно в лайве.

## Ветки развития (решаем после пробы)
- **Глиф-нажатие доступно лайв** → оверлей «кто слил» (мем-фича, вирусный контент).
- **Недоступно** → пивот на лайв-оверлей полезных таймеров (кд глифа/скана как факт «доступен/на кд», рошан-таймер, тайминги предметов, статус байбека, power-spike алерты) + опционально пост-гейм «кто слил» из реплея.

## Контент-угол
Build-in-public: снимать процесс с первой секунды (как гуглю GSI, как пробую, где стенка). Аудитория — русскоязычные дотеры. Каждый исход = клип (получилось → тул; не получилось → «почему Valve прячет»). Метрика — выпущенные клипы, не просмотры.
